# Sora Model Folder Layout

**Fact or rule:** Kvon (November 18): "organize all the folders in Sora's folder into folders that correlate to the feature/animation that is being referenced." `design/models/sora/` version folders now sit in feature groups: `attacks/<standing|crouching|jumping>_<light|medium|heavy>/`, `attacks/saved_attacks/`, `grabs/ground_grab/`, `grabs/air_grab/` (incl. the miss pose), `guard/`, `hurt/`, `movement/{walk_shuffle,crouch,glide,jump,double_jump,air_dash,back_dash}/`, `idle/` (battle_v12, sprite2d_v3), `model/from_scratch_blockout/`, `combat/boxes_preview/`, `research/` (gemini_animation, gemini_walk_review, momask_trial, pose_edit). `blender_workflow/` and `downloads/` stay at the top.
- **How the scripts cope:** `blender_workflow/sora_paths.py` - its `SORA` object maps `SORA / '<version name>[/file]'` to the name's group (first matching name start wins; unknown names stay at the top), so every script still names a version folder alone and new builds land in their group. All active scripts import it (`SORA = ...` lines). Self-check: `python blender_workflow/sora_paths.py`. When adding a new kind of animation, add its name start to GROUPS.
- **The .blend files store texture paths relative to themselves** (`//..\downloads\...`): moving them deeper broke the textures (a test render reported "Failed to load 6 image files"); all 74 were re-pointed and re-saved (scratch relink_blends.py: old location = design/models/sora/<name>). Move a .blend again -> re-point its images.
- Verified after the move: make_boxes, both grab exports, grab effects and review sheets reproduce byte-identical files; a Blender render loads every texture. 3,521 files were pure renames. The Gemini browser tool's reference image paths (gemini_cdp.mjs) now point into `research/`.
- **Memory notes written before November 18 use the old flat paths** (e.g. `atk_agrab2d_v12/...` = `grabs/air_grab/atk_agrab2d_v12/...`).

**Why:** Kvon's request; no further reason given.
